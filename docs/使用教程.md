# HarnessNovel 使用教程

这是一套基于 Python 和 OpenAI 兼容接口的长篇网文创作工作台。推荐先使用桌面版熟悉流程，再根据需要使用命令行批处理。

## 1. 环境要求

- Windows 10/11
- Python 3.9 或更高版本，推荐 Python 3.12
- 可访问模型服务商 API 的网络
- Windows 桌面版需要 Microsoft Edge WebView2 Runtime

源码版首次安装可以直接双击项目根目录的 `start_desktop.cmd`。脚本会检查 Python、安装当前源码和桌面依赖，然后启动独立窗口。

如果系统找不到 Python，可以在 PowerShell 执行：

```powershell
winget install --id Python.Python.3.12 -e
```

安装后请关闭并重新打开 PowerShell，让新的 `PATH` 生效，然后确认：

```powershell
python --version
python -m pip --version
```

如果 `python` 打开 Microsoft Store 而不是显示版本号，请先关闭旧终端再重试；
源码版也可以直接双击 `start_desktop.cmd`，启动脚本会自动避开该占位别名。

也可以手动安装源码依赖：

```powershell
cd R:\UnityProject\pikachuNovel
python -m pip install --upgrade ".[desktop]"
```

## 2. 配置模型 API

首次配置执行：

```powershell
python novel_cli.py config
```

这会创建：

```text
%USERPROFILE%\.harnessNovel\.env
```

至少填写以下三组配置。可以全部使用同一个服务商，也可以把轻量任务和高质量任务分给不同模型：

```ini
DATA_BUILDER_MODEL=your-fast-model
DATA_BUILDER_BASE_URL=https://api.example.com/v1
DATA_BUILDER_API_KEY=your-api-key

ADAPTIVE_BUILDER_MODEL=your-quality-model
ADAPTIVE_BUILDER_BASE_URL=https://api.example.com/v1
ADAPTIVE_BUILDER_API_KEY=your-api-key

ADAPTIVE_BUILDER_LITE_MODEL=your-fast-model
ADAPTIVE_BUILDER_LITE_BASE_URL=https://api.example.com/v1
ADAPTIVE_BUILDER_LITE_API_KEY=your-api-key
```

配置含义：

- `DATA_BUILDER`：参考小说拆解、事实卡片和资料提取。
- `ADAPTIVE_BUILDER`：全书设计、世界观、长线主线和舞台设计，建议使用质量更高的模型。
- `ADAPTIVE_BUILDER_LITE`：故事情节单元、章纲、正文和人化处理，建议使用速度快、价格低的模型。

Web 工作台右上角也可以修改这些配置。保存后会立即作用于当前进程。

### 从 CC Switch 导入

如果电脑安装了 [CC Switch](https://github.com/farion1231/cc-switch)，打开右上角“大模型 API 配置”，可以在“从 CC Switch 导入”中分别为参考拆解、全书设计和轻量生成选择一个 Codex 供应商，然后点击“验证并导入”。

导入过程会：

1. 只读访问默认位置 `~/.cc-switch/cc-switch.db`，不会修改 CC Switch 数据库。
2. 从所选 Codex 供应商提取默认模型、Base URL 和 API Key；API Key 只在本地后端处理，不会发送给浏览器。
3. 自动尝试把 Responses API 根地址适配为 Chat Completions 常用的 `/v1` 地址。
4. 每个不同供应商执行一次最多 2 token 的最小真实调用。全部验证成功后才写入 HarnessNovel，验证失败不会覆盖现有配置。

只有同时配置了 Key、默认模型和 Base URL 的 Codex 供应商可以选择。部分供应商只支持 Responses API、不支持 Chat Completions，这类配置会在验证阶段被拒绝。CC Switch 使用自定义数据目录时目前不会自动发现，可以继续使用下方手动配置方式。

## 3. 启动方式

### 桌面版

```powershell
python novel_cli.py desktop
```

或者双击：

```text
start_desktop.cmd
```

### 浏览器版

```powershell
python novel_cli.py web
```

浏览器打开 `http://127.0.0.1:8765`。如果端口被占用，可以指定其他端口：

```powershell
python novel_cli.py web --port 8766
```

也可以指定工作区根目录：

```powershell
python novel_cli.py web --workspace-root D:\my-novels
```

## 4. 创建工作区

命令行创建空工作区：

```powershell
python novel_cli.py init my-first-novel
```

查看已有工作区：

```powershell
python novel_cli.py list
```

Web 工作台中点击“新建工作区”也可以完成同样操作。每本小说互相独立，默认根目录是当前目录下的 `my-novels`；Web 版首次启动通常使用用户文档目录中的 `my-novels`。

## 5. 推荐创作流程

### 第一步：拆解参考小说

准备一个章节标题清晰的 `.txt`、`.md` 或其他纯文本小说文件，然后执行：

```powershell
python novel_cli.py init my-first-novel --txt D:\novels\reference.txt
```

拆解流程会生成：

1. 章节事实卡片。
2. 故事片段和情节单元。
3. 分卷结构、卷纲和全书大纲。

拆解过程支持断点恢复。参考文件更新后，可以重新执行 `init`，或者使用：

```powershell
python novel_cli.py reference-resume my-first-novel
```

参考文件必须是你有权使用的内容。拆解结果用于学习叙事结构、节奏和写作规律，不是直接复制原文。

### 第二步：可选导入目标题材资料

如果新书需要一个较完整的目标世界观，可以导入资料文件或资料目录：

```powershell
python novel_cli.py world-import my-first-novel D:\materials\xianxia
python novel_cli.py world-build my-first-novel
```

支持常见文本和结构化文件，例如 `.txt`、`.md`、`.json`、`.jsonl`、`.yaml`、`.csv`。资料库完成后，系统会在全书设计、故事单元、章纲和正文阶段检索少量相关事实。

### 第三步：填写创作方向

可以在工作区根目录创建 `creative_direction.md`，也可以在 Web 对话框中直接输入。建议包含：

- 题材和读者定位。
- 主角身份、核心欲望和主要困境。
- 希望保留的参考作品特征。
- 希望主动改变的部分。
- 禁止出现的元素或内容边界。

### 第四步：生成全书设计

最简单的完整命令是：

```powershell
python novel_cli.py novel-outline my-first-novel
```

它会生成核心玩法、长线主线、舞台路线图、角色成长线以及书名和简介。也可以拆成更细的步骤：

```powershell
python novel_cli.py design-concept my-first-novel
python novel_cli.py stage-design my-first-novel
python novel_cli.py story-design-extend my-first-novel
```

生成后建议先人工检查 `file_system/story_design/` 下的文件，再进入分卷创作。修改全书设计后，后续舞台和情节单元可能需要重新生成。

### 第五步：生成指定分卷

```powershell
python novel_cli.py volume-outline my-first-novel --volume 1
python novel_cli.py story-arcs my-first-novel --volume 1
python novel_cli.py chapter-outlines my-first-novel --volume 1
python novel_cli.py write my-first-novel --volume 1
```

生成顺序不能颠倒：卷纲是故事单元的输入，故事单元是章纲的输入，章纲是正文的输入。

正文默认会执行人化处理。只生成原始正文可使用：

```powershell
python novel_cli.py write my-first-novel --volume 1 --no-humanize
```

只生成前几章用于试写：

```powershell
python novel_cli.py write my-first-novel --volume 1 --start 1 --max 3
```

### 第六步：通过 Web 对话迭代

Web 工作台适合反复调整：

- 全书设计：修改玩法、世界观、主线和舞台。
- 故事情节：调整某一卷的情节单元。
- 章纲：调整某一个情节单元覆盖的章节。
- 正文：生成、续写或局部修改正文。

任务运行时可以暂停、恢复或停止。右上角“任务与日志”可以查看实时输出、复制日志和查看实际发送给模型的 Prompt。

## 6. 工作区文件位置

每本小说通常位于：

```text
my-novels/<工作区名>/
├─ creative_direction.md
├─ reference/
│  ├─ sample_novel.txt
│  ├─ chapters/
│  └─ outlines/
└─ file_system/
   ├─ story_design/
   ├─ world_knowledge/
   ├─ story_arcs/vol_XX/
   ├─ chapter_outlines/vol_XX/
   ├─ chapters/vol_XX/
   ├─ writing/
   └─ adaptation/
```

不要手动删除 `analysis_state.json`、`design_state.json`、使用状态文件或任务日志，除非你明确要强制重建。删除生成文件后，下一次任务通常会将其视为未完成并重新生成。

## 7. 常见问题

### 双击启动仍提示 Python 不存在

关闭所有旧 PowerShell 和命令提示符窗口后重新打开，再运行：

```powershell
python --version
```

如果命令仍不可用，直接使用 Python 安装目录运行：

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -m pip install --upgrade ".[desktop]"
```

### 依赖安装失败

在项目目录手动运行安装命令，查看完整错误：

```powershell
python -m pip install --upgrade ".[desktop]"
```

网络代理、证书拦截和公司网络通常是主要原因。

### 桌面窗口空白或无法创建

安装或修复 Microsoft Edge WebView2 Runtime，然后重启桌面版。也可以先使用浏览器版确认 Python、API 和工作区配置正常。

### 生成任务失败

先检查右上角任务日志。常见原因是 API Key、Base URL、模型名、账户余额或模型不支持 JSON 输出。修正配置后可以从当前阶段继续，不必从头拆解。

模型 API 的单次调用默认最多尝试 3 次（首次调用加 2 次重试）。日志会显示“第 N/3 次调用”、失败原因和下一次等待时间。两次重试前默认分别等待 1.5 秒和 3 秒；等待模型响应时，每 10 秒记录一次等待状态。

以下确定性错误不会重试，而是立即把当前任务标记为失败：HTTP 400、401、402、403、404、405 和 422。网络中断、超时、限流和服务端错误会在上限内重试。重试耗尽后任务会停止，不会再被上层当作空输出重复请求。

Web 对话任务运行时可以点击“暂停”。系统会取消当前模型请求并停在最近的已落盘断点；点击“继续”后只重新执行尚未完成的当前步骤。点击“结束”会保留已经生成并写入工作区的内容。

参考小说导入、拆解和其他命令行后台任务运行时，打开右上角“任务与日志”，选中运行中的任务后点击“停止任务”。这类任务不支持暂停，但停止后会保留已经写入的拆解结果；修正配置后使用“继续拆解”即可从断点接着执行。

OpenAI 兼容服务的 Base URL 必须使用服务商指定的 API 根地址，常见格式是 `https://example.com/v1`。如果日志提示“返回的不是 OpenAI 兼容响应”或 `'str' object has no attribute 'choices'`，优先检查地址是否遗漏 `/v1`，不要反复启动任务。

### 想强制重建

CLI 的多数生成命令支持 `--force`，但强制重建会覆盖对应阶段的现有产物。建议先复制工作区，再执行：

```powershell
python novel_cli.py story-arcs my-first-novel --volume 1 --force
```

## 8. 建议的首次试跑

第一次使用时，不要直接生成整本书，建议只拆解少量章节并试写一小段：

```powershell
python novel_cli.py init demo --txt D:\novels\reference.txt --max-chapters 20
python novel_cli.py novel-outline demo
python novel_cli.py volume-outline demo --volume 1
python novel_cli.py story-arcs demo --volume 1
python novel_cli.py chapter-outlines demo --volume 1
python novel_cli.py write demo --volume 1 --start 1 --max 3
```

确认模型配置、输出风格和上下文长度都合适后，再扩大拆解范围和正文生成范围。
